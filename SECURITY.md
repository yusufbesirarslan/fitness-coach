# Security Policy

Security and user privacy are important parts of AxisAI's architecture.

If you believe you have discovered a security vulnerability, please report it privately rather than opening a public GitHub issue.

## Reporting a vulnerability

Send the report to:

**security@axisaiapp.com**

Please include, where possible:

* a description of the vulnerability
* the affected component or endpoint
* steps to reproduce the issue
* the potential security or privacy impact
* any proof-of-concept material required to reproduce it
* suggested remediation, if known

Please do not include real user credentials, authentication tokens, private user data, or other unnecessary sensitive information.

## Please do not

When researching or reporting a vulnerability, do not:

* access or modify data belonging to another user
* perform destructive testing
* intentionally degrade service availability
* perform denial-of-service testing
* publish the vulnerability before it has been reviewed
* use compromised credentials or social engineering

## Scope

Security reports may include issues involving:

* authentication or authorization
* cross-user data access
* sensitive information exposure
* injection vulnerabilities
* server-side request forgery
* insecure file or media access
* privilege escalation
* session or credential handling
* API authorization boundaries
* privacy-impacting application behavior

General bugs, feature requests, or product feedback should use the normal GitHub issue process instead.

## Response

Valid reports will be reviewed and prioritized according to their severity, exploitability, affected users, and potential privacy impact.

Please allow reasonable time for investigation and remediation before public disclosure.

## Supported versions

AxisAI is currently under active development.

Only the current production version and the current main development line are considered supported for security fixes unless explicitly stated otherwise.
