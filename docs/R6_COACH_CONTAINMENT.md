## What the proof measures

The registry resolves `AI_COACH_PLAN_MUTATION_TOOLS_ENABLED` into Flask config during factory initialization. Gunicorn's single, non-preloaded serving child reads that config in its own app context. The worker initializes the actual `app.jobs.tasks._worker_app` through `_in_app_context` before heartbeat or queue consumption. RQ work horses inherit the cached app. The protected worker rejects SimpleWorker. Its boot-time read-only schema and ACL checks use the real pool, which it disposes before fork. The on-demand worker challenge rechecks the cache pointer and the loaded flag and guard without reopening that pool. The web challenge checks the live schema through the serving pool.

Both processes require the literal Boolean `False` in loaded config and an actual `False` result from `plan_mutation_tools_enabled()`. The same guard fences provider tool publication, execution and proposal and confirmation paths. On protected actors it stays closed if the loaded flag later changes. Ordinary actors retain the existing guard behavior. The private Unix socket is mode 0600 and accepts an unpredictable challenge. The host verifier checks its Linux peer PID and namespace process lineage and start ticks around the read. The host then checks Docker container ID, immutable image, start time, health, restart count and OOM status on both sides of each read. It joins the result to the approved source SHA/tree and schema heads and verifies canonical slot and route and both inventories around pair collection. The exact proof only exposes source and process identities, a boot hash, schema heads and two Boolean fields per app. The listener omits environment, app or health payloads, credentials, raw latch nonces, exceptions, and user data.
