# Synthetic workflow and customer quality qualification

All providers are fake SDKs; no personal data, real images, paid model invocation or live consent policy is used. Fixtures exercise actual application prompt builders and parsers where stated. “Completion” below means deterministic application completion on those fixtures, not an observed production success rate or a live-model clinical/nutritional quality claim.

The QR content fixture maps only synthetic menu/nutrition disclosure authority and admission generation. Production D1 does not have that approved composite mapping; its refusal remains a launch gap. Content tests serialize batch workers because a machine-induced 2-second D1 lock timeout correctly refused a concurrent batch. Parallel budget tests independently arbitrate the shared vector; production D1 contention and client latency still require qualification. We do not weaken the consent timeout or broaden the runtime registry.

These retained per-call output allocations are the existing useful service budgets, not newly measured minimum sufficient tokens. Ordinary and heavy mocked answers parse and preserve required fields, but a synthetic fake can return the requested document regardless of model behavior. Live blind answer review, token/latency distributions, actual output truncation, EN/TR error presentation and observed completion/failure rates remain mandatory before selling the service. Budget and quality should be calibrated together against authorized representative frozen payloads; no expected financial mean is treated as proof of fit.

Boundary tests demonstrate all five resource components, exact last admission, one-over no-SDK refusal, frozen payload mutation protection, model/routing/cache rejection, and authoritative output reservation before the response. Customer error tests ensure HTTP 422 / nonretryable `AI_ACTION_BUDGET_EXHAUSTED`, with no partial success payload. Zero-attempt failures do not deduct a visible allowance; uncertain attempts retain original UNKNOWN settlement semantics and finite release policy. Same-key native failure/success replay generates no new call. A new logical customer request remains governed by the original allowance and policy, not an invented dollar-based subscriber quota.

The 20-Coach weekly target remains plausible for the synthetic ordinary/tool-heavy workflows under this per-action envelope; it has not been commercially accepted. Full-use economics remain negative at current prices/routing. The package reports that conflict without reducing Coach units or treating a refusal as successful service.
