## Implementation

- Coach keeps one original operation authority. Re-entering the same operation validates/reuses it; a different purpose cannot be recaptured inside it. Supported first-party tool dispatch checks owner and original authority before execution; existing writer/confirmation fences remain. Food lookup/staging, gym-photo analysis and Memory are removed from both provider tool schemas and refused on stale/forged dispatch names. This bounds only unqualified capabilities. Existing plan mutation action/confirmation authority stays intact, without creating another plan-generation operation.
- QR physical `nutrition` calls resolve to the original `menu_extract` binding: purpose remains `qr_menu.analysis`, with exactly its ordered categories, original version/generation, model/recipient and owner. Generic Nutrition remains unbound. Existing action/worker scope and physical accounting are reused. Optional FatSecret/proxy lookup is skipped inside D1 operations, including OAuth acquisition; bounded AI estimation remains available. No proxy identity or terms were invented.
- Non-AI menu website acquisition requires an explicitly approved `external_scopes=("public_https_menu_source",)` in the SAME immutable QR contract. That new scope identifier is a source capability, not an assertion of vendor/geography facts. It covers public HTTPS text/HTML menu websites under the existing DNS/connected-peer, redirect, byte/request/deadline and media restrictions; each parent fetch runs under the original D1 generation. Scope addition changes the contract digest and requires affirmative consent. No scope or disclosure is published here. It cannot authorize FatSecret, health-target disclosure, images, OCR or PDF processing.
- Source-selected exact launch versions are held in `ai_consent_disclosures.LAUNCH_VERSIONS`, initially empty. Historical contracts can remain in the existing policy registry, but only the selected version is offered for a new grant/launch admission. Dispatch and canonical/socket publication also require the exact published EN/TR bytes to remain available.
- Only the five named native endpoints may pass the existing global closure, and only after installed finite source policy, exact source-selected published contract/grant, signed cohort and enforcement/Redis readiness checks. Unsupported browser/legacy, streaming, replacement, comparison, Memory and OCR paths remain closed. Subsequent existing domain admission, fresh subscription selection, logical/physical reservation, spend guard, provider check and settlement stay authoritative. No second ledger or provider architecture was introduced.
- Canonical signed adult/TR eligibility is read freshly from the database inside the existing D1 account transaction at capture, physical dispatch and publication. Source-installed Starter/Premium allocations enforce the same cohort under the existing ledger owner lock. Client claims, mutable profile declarations, a Premium boolean or a consent grant cannot promote an account. Missing/tampered/foreign/unsupported-version, minor, non-TR, contradictory, future/naive/malformed evidence refuses with `AI_SERVICE_ELIGIBILITY_REQUIRED`. Account-management/non-AI routes are unchanged.

Existing consent dispatch already holds its cross-process account fence through a bounded SDK call; this PR preserves that protocol and adds no domain/ledger lock across model I/O. Existing logical holds, UNKNOWN/billed failure accounting, last-unit protection, one-time Starter, no stacking and calendar-month behavior remain unchanged. Task 29's zero-attempt settlement path is not duplicated or changed.
